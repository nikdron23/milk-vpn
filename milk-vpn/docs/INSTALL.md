# Установка Milk VPN на VPS — пошагово

Сервис состоит из двух частей:

| Часть | Что это | Где живёт |
|---|---|---|
| **Управляющий сервер** | сайт, личный кабинет, Telegram-бот, админ-панель, приём оплаты | один небольшой VPS (1 vCPU, 1 ГБ ОЗУ, 10 ГБ диска, Ubuntu 22.04/24.04) |
| **VPN-серверы (ноды)** | панели 3x-ui, через которые идёт трафик пользователей | отдельные VPS в разных странах (по одному на страну) |

Управляющий сервер сам создаёт и продлевает клиентов на всех нодах и отдаёт пользователям единую ссылку-подписку со всеми странами.

> **Важно.** Управляющему серверу нужны порты **80 и 443** (сайт и HTTPS-сертификат). Если на VPS уже работает 3x-ui на порту 443, поставьте управляющий сервис на **отдельный** VPS — установщик предупредит о конфликте.

---

## Что понадобится заранее

1. **VPS** для управляющего сервиса (любой провайдер) — запомните его IP.
2. **Домен** (например, `vpn.example.com`) — A-запись должна указывать на IP этого VPS.
3. **Telegram-бот** — токен от [@BotFather](https://t.me/BotFather) и ваш Telegram ID (узнать у [@userinfobot](https://t.me/userinfobot)).
4. **Магазин в Робокассе** (можно подключить позже; для проверки используется тестовый режим).
5. **Один или несколько VPS для VPN-серверов** — см. [NODES.md](NODES.md).

---

## Шаг 1. DNS

В панели вашего регистратора/DNS создайте запись:

```
Тип: A     Имя: vpn (или @)     Значение: IP_вашего_VPS
```

Проверить: `ping vpn.example.com` — должен показать ваш IP (обновление DNS занимает от минут до часа).

## Шаг 2. Загрузите проект на VPS

Подключитесь к VPS по SSH (`ssh root@IP_VPS`) и убедитесь, что есть `unzip`:

```bash
apt-get update && apt-get install -y unzip
```

С вашего компьютера отправьте архив (Windows PowerShell / macOS / Linux):

```bash
scp milk-vpn.zip root@IP_VPS:/root/
```

(на Windows можно использовать WinSCP — перетащите архив в `/root`). На VPS:

```bash
cd /root
unzip milk-vpn.zip
cd vpnshop
```

## Шаг 3. Запустите установщик

```bash
sudo bash deploy/install.sh
```

Скрипт задаст вопросы (Enter — значение по умолчанию):

| Вопрос | Что ввести |
|---|---|
| Домен сервиса | `vpn.example.com` |
| Название сервиса | `Milk VPN` |
| Токен бота | из @BotFather |
| Ваш Telegram ID | число, например `123456789` |
| Username поддержки | без `@` (можно пропустить) |
| Логин/пароль админа | пароль можно сгенерировать автоматически — он будет показан в конце |
| Робокасса | можно пропустить и вписать позже в `/opt/milkvpn/.env` |

Что делает установщик: ставит Docker, проверяет домен/порты/токен бота, копирует проект в `/opt/milkvpn`, создаёт `.env` (права 600), открывает 80/443 в ufw (если он включён), включает ежедневный бэкап базы и запускает контейнеры. В конце он напечатает адреса и пароль админа.

Первая сборка занимает 1–3 минуты; сертификат HTTPS выпускается автоматически (до пары минут).

**Установщик можно безопасно запускать повторно** — он предложит сохранить текущие настройки.

## Шаг 4. Подготовьте VPN-серверы

Для каждой страны: арендуйте VPS, поставьте 3x-ui (скрипт `deploy/install-node.sh`) и создайте inbound VLESS + Reality. Пошаговая инструкция — в [NODES.md](NODES.md).

## Шаг 5. Добавьте серверы в админ-панели

1. Откройте `https://vpn.example.com/admin`, войдите.
2. «Серверы» → «Добавить сервер»: название (`Нидерланды`), страна (флаг), адрес панели 3x-ui, логин, пароль, ID inbound, flow, домен ноды.
3. После сохранения увидите проверку связи с панелью. Статус «онлайн» — всё хорошо.

Все уже выданные ключи автоматически появятся на новом сервере (в фоне, до 5 минут, или кнопка «Синхронизировать»).

## Шаг 6. Робокасса

В личном кабинете Робокассы → *Мои магазины → Технические настройки*:

| Поле | Значение |
|---|---|
| Result URL | `https://vpn.example.com/payment/result` (метод **POST**) |
| Success URL | `https://vpn.example.com/payment/success` |
| Fail URL | `https://vpn.example.com/payment/fail` |
| Алгоритм подписи | тот же, что в `ROBOKASSA_ALGO` (md5 / sha256 / …) |

Данные магазина (идентификатор, пароли #1 и #2, тестовые пароли) вписываются в `/opt/milkvpn/.env`, после чего:

```bash
cd /opt/milkvpn && docker compose --profile https up -d
```

Сначала держите `ROBOKASSA_TEST=true` и проведите тестовый платёж. Когда всё работает — поменяйте на `false` и перезапустите.

## Шаг 7. Проверка

1. Напишите боту `/start` → «🎁 Пробный период» — бот пришлёт ссылку-подписку.
2. Добавьте ссылку в приложение **Hiddify** (или другое) — должны появиться все ваши страны.
3. В боте «🛒 Купить» → тестовый платёж → ключ должен прийти автоматически.
4. В админке «Заказы» заказ станет «оплачен».

## Обслуживание

Все команды — из папки `/opt/milkvpn`.

| Задача | Команда |
|---|---|
| Логи в реальном времени | `docker compose logs -f vpnshop` |
| Перезапуск | `docker compose --profile https restart` |
| Остановка | `docker compose --profile https down` |
| Изменить настройки | `nano .env`, затем `docker compose --profile https up -d` |
| Бэкап базы вручную | `./deploy/backup.sh` (файлы в `backups/`) |
| Обновление | замените файлы проекта (не трогая `.env`), затем `./deploy/update.sh` |

**Бэкапы** делаются автоматически каждый день в 04:17 и хранятся 14 дней. Копируйте папку `/opt/milkvpn/backups` и файл `/opt/milkvpn/.env` к себе периодически.

**Восстановление базы:**
```bash
cd /opt/milkvpn
docker compose --profile https stop vpnshop
docker run --rm -v milkvpn_vpnshop_data:/data -v "$PWD/backups":/b alpine \
  cp /b/vpnshop-ГГГГ-ММ-ДД_ЧЧММ.db /data/vpnshop.db
docker compose --profile https start vpnshop
```
(имя тома может отличаться: `docker volume ls | grep vpnshop`.)

**Не меняйте `SECRET_KEY`** после запуска — им зашифрованы пароли серверов в базе. Если всё же сменили, откройте каждый сервер в админке и введите пароль заново.

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| Сайт не открывается по HTTPS | DNS (`ping домен` показывает IP сервера?), открыты ли 80/443 в файрволе провайдера, `docker compose logs caddy` |
| Бот молчит | `docker compose logs vpnshop` — верный ли `BOT_TOKEN`; нет ли второго экземпляра бота с тем же токеном |
| В админке сервер «недоступен» | Адрес панели **вместе с секретным путём**, логин/пароль, не включена ли в 3x-ui двухфакторная аутентификация; для самоподписанного сертификата снимите галочку «Проверять TLS» |
| После оплаты ключ не пришёл | «Заказы» → «Выдать вручную» (сначала проверьте платёж в Робокассе). Причина обычно в недоступном сервере — Робокасса сама повторит запрос, как только сервер заработает |
| Робокасса «bad signature» | Совпадают ли пароли #1/#2, алгоритм подписи и режим (тест/боевой) |
| В приложении пустая подписка | Есть ли активные серверы с inbound **VLESS**; `docker compose logs vpnshop \| grep подписк` |

## Юридическое замечание

Сервис — технический инструмент. Законодательство о VPN и о рекламе таких сервисов отличается в разных странах, а Робокасса и другие платёжные системы имеют собственные правила для подключаемых магазинов. Убедитесь, что ваша деятельность им соответствует. Тексты страниц «Условия использования» и «Конфиденциальность» — типовые заготовки: проверьте и доработайте их под свой бизнес (файлы `app/templates/terms.html`, `app/templates/privacy.html`).
